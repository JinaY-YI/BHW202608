# EMS 主站（学生 B）—— 南极考察站微电网智能调控系统

能量管理系统（EMS）主站：实时采集电网模拟器遥测/遥信，按“风电优先、柴发补偿、
保留备用”原则生成风/柴调度策略，并以遥调指令下发回电网模拟器。

> 通信协议遵循《南极考察站微电网-变量字典与通信协议-修订版V3.md》。

## 0. 先分清：哪些是“正式程序”，哪些是“测试脚手架”

| 目录/文件 | 性质 | 说明 |
| :--- | :--- | :--- |
| `ems/`（除 `mock_grid.py`） | **正式程序** | EMS 主站全部业务代码，无 `test` 前缀 |
| `run_ems.py` / `run_demo.py` | **正式入口** | 启动 EMS 主站 |
| `ems/mock_grid.py` | 测试/演示辅助 | 内置电网模拟器仿真桩，仅用于**无联调环境时独立演示** |
| `tests/test_*.py` | **测试脚手架** | 每个模块的单元测试（`test_` 前缀是 unittest 约定，不影响正式运行） |

**联网联调时，正式程序只用到 `ems/`（不含 mock_grid）+ `run_ems.py`**，
完全不需要 `tests/`。测试与仿真桩只是让你在没有学生 A/C 的机器上也能先跑通、
先自测。

- Python 3.10+（标准库即可，无第三方依赖）
- 数据库：SQLite（`ems.db`）
- 界面：tkinter（Python 自带）

## 3. 三种运行方式

### 3.1 图形界面（默认，整体查看）

```bash
python run_ems.py
```

启动后自动以“内置仿真桩”模式运行，界面顶部是**连接控制**，可随时切换：

- **内置仿真桩（独立演示）**：不依赖学生 A/C，一键演示闭环；
- **电网模拟器（联调学生 A）**：填写学生 A 的 IP 与端口 `8888`，点“▶ 启动”。

界面分四个页签：实时监控（状态/SCADA/评价/曲线）、调度配置、历史曲线、运行日志。

### 3.2 控制台演示（打印具体数值，无界面）

```bash
python run_demo.py
```

约 40 秒，依次演示 无风/适宜风/高风高负荷/低负荷/中等风速 五种工况，控制台实时
打印表格（风速/负荷/风机/柴发/设定值/可用风/备用），结尾输出各工况的调度摘要。

### 3.3 无界面运行（服务器/测试）

```bash
python run_ems.py --headless --mock                     # 内置仿真桩，控制台打印实时表格
python run_ems.py --headless --host 192.168.1.10        # 连接真实电网模拟器
```

## 4. 与其他两台电脑联网（联调步骤）

三机 + 单片机通过无线局域网互联，电网模拟器是 TCP Server（端口 `8888`），
EMS 主站是 TCP Client。

1. **学生 A（电网模拟器）**：在其计算机上启动，确认监听 `8888`，记下其局域网 IP；
2. **学生 C（风机控制器 + 上位机）**：单片机/上位机各自就绪，风机控制器连接电网模拟器；
3. **学生 B（本 EMS 主站）**：任选一种方式填入学生 A 的 IP：
   - 图形界面：顶栏选择“电网模拟器”，地址填学生 A 的 IP，端口 `8888`，点“▶ 启动”；
   - 命令行：`python run_ems.py --host <学生A的IP> --port 8888`
     （无界面加 `--headless`）。

启动后 EMS 自动完成：握手 `hello` → 参数查询 `param_query` → 每秒 `yc_yx_request`
→ 每 5 秒调度决策 → `command` 遥调下发 → 心跳保活 / 断线重连。界面“实时监控”页
即可看到连接状态与实时数据。

> 说明：本模块只负责“电网模拟器 ↔ EMS”这一段。风机控制器（学生 C）是电网模拟器
> 的另一路 TCP 客户端，由学生 A 的模拟器统一汇聚，EMS 无需直接连接风机控制器。

## 6. 联调排障（与学生 A 对不上时的定位方法）

现象常有两种：**曲线只有启动时更新、之后一直直线**，或**下发调度指令一直收不到回执**。
绝大多数是两边对“序号(seq)增量机制”或“命令回执类型名”的理解不一致。定位方法：

```bash
# 1) 抓取与电网模拟器的原始收发报文（最直接）
python diag_comm.py --host <学生A的IP> --port 8888 --seconds 20

# 2) 或在运行 EMS 时把每条报文全文写进日志，再到界面“运行日志”页查看
python run_ems.py --host <学生A的IP> --port 8888 --trace
```

然后对照 V3 协议核对：

- `yc_yx_response` 里 `data.seq` 是否随变位递增、`data.yc`/`data.yx` 字段名是否一致；
- 下发 `command` 后，对端是否返回 `type: "command_response"`（若返回的是别的 type，日志会
  以 WARN 打印“收到未识别报文类型…”的全文，据此改对端或改本端）；
- 若 `yc_yx_response` 只收到 1 条就停，多半是对端 seq 语义不同——本端已改为**只要收到数据
  就按绝对值更新**，曲线不会因序号跳变而停更，但仍建议双方统一 seq 口径。

> 本端 `ems/mock_grid.py` 是一份按 V3 协议实现的仿真桩，可作为学生 A 侧实现的对照。

## 7. 设计要点

- **计算权责**：EMS 只下发遥调（`wtg_power` / `diesel_power` 出力设定值），不下发启停遥控；
  风机启停/桨距角由风机控制器决策，柴发启停由电网模拟器决策；设备参数以 `param_notify` 为准。
- **调度策略**（`strategy.py`）：风电优先 → 柴发补偿 → 保留备用（柴发维持最小出力作旋转备用），
  目标限幅于 `0~rated_power` 与 `diesel_min~diesel_max`，能力不足时记录缺额 `shortfall`。
- **通信**（`operator_io.py`）：1s 遥测增量/变位 + 断点补传、序号跳变自动重传、
  5s 心跳、15s 断线判定、1s/2s/4s…退避重连、重连复位 seq=0。

## 8. 验收对照

| 验收项 | 落实 |
| :--- | :--- |
| 测量-决策-执行-反馈闭环 | `yc_yx_request/response` → 调度决策 → `command` → 电网模拟器执行 |
| 接口一致性 | 变量名/单位/归属与 V3 字典一致 |
| 运行合理性 | 目标限幅于能力范围，风速/负荷变化响应方向正确 |
| 数据库读写 | EMS 独立读写 `ems.db`，SCADA 经 TCP 同步 |
| 硬件参与 + 断开识别 | 心跳超时/断线告警、退避重连（集成测试覆盖） |
| 可观察与追溯 | 界面实时查看 + 历史/调度历史/日志三表覆盖完整闭环 |
